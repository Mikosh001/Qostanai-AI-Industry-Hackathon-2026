# Финальная приёмка и пилот / Финалдық қабылдау және пилот

Статус: план с целевыми критериями. Ни согласование КРУ, ни результаты этого пилота не заявлены как состоявшиеся.

## Что доказываем жюри за 3 минуты

| Время | Действие | Проверяемое утверждение |
|---|---|---|
| 0:00-0:25 | Проблема: обычный тест не защищает рабочую среду и не объясняет подозрительный эпизод | Sergек дополняет существующий Moodle, не заставляя вуз переносить вопросы |
| 0:25-0:50 | Короткая схема: локальный анализ → университетский хаб → решение преподавателя | Где анализ, данные и окончательное решение |
| 0:50-1:15 | Уже открытый локальный Moodle: test selection → фото → Start attempt | Нет ручного URL/режима/teacher password у студента; контроль начинается в нужный момент |
| 1:15-1:40 | Телефон 5-7 с; кратко показать заблокированную комбинацию | Phone flag отличается от технической блокировки |
| 1:40-2:10 | Отправка → преподаватель → камера/экран/звук эпизода | Сохранились start/end, контекст и возможность отклонить AI-событие |
| 2:10-2:35 | Подписанный JSON, device revoke и таблица проверок | Проверяемая целостность и контроль допуска |
| 2:35-3:00 | Пилот, измеряемая польза, границы | Не обещать неподтверждённую точность/масштаб или экономию |

Резервная запись должна содержать реальные действия интерфейса. Если используются camera fixtures или отключён native guard, условия нужно сообщить. Запись не заменяет доказательство OS enforcement. Не выполнять спонтанные USB/RDP/перезапуски на сцене без предварительной приёмки.

## Пилот на 30 студентах: два занятия

Владелец со стороны университета: LMS-администратор; принимающий: преподаватель; оператор: сотрудник аудитории. Имена и согласование заполняет университет. Сначала одна управляемая аудитория Windows, одна версия Moodle, одинаковый набор вопросов. Platonus подключается отдельным этапом после тестового доступа.

1. Обычная работа с LMS: измерить подготовку, технические обращения и время ручной проверки контрольных эпизодов.
2. Sergек на тех же рабочих местах: нормальная сдача и заранее согласованные действия телефона/второго человека/звука, без влияния на настоящую оценку студента.
3. Разметку делает человек до чтения AI-флагов. Спорные эпизоды проверяет второй человек. Для повторного улучшения порогов выделяется отдельный материал; итоговый holdout не используется для настройки.

| Метрика | Как считать | Предлагаемый критерий, не результат |
|---|---|---|
| Успешная сдача | Завершённые без техпрерывания / начатые | 30/30 в двух занятиях |
| Старт | От Start attempt до доступного первого вопроса, отдельно native/CV | p95 ≤ 15 с на целевых ПК |
| Phone episode recall | Найденные размеченные показы / все показы, отдельно front/back/partial | ≥ 90%; показать число эпизодов и доверительный интервал |
| Ложные события | Ошибочные review flags / часы обычной работы | Цель ≤ 1/час; для убедительного вывода нужно достаточно часов, одного короткого видео мало |
| Полнота доказательств | Доступные camera/screen/audio context / события, где они требуются | 100% либо явная отметка incomplete |
| Время review | Время преподавателя на одинаковые размеченные эпизоды | Сравнить до/после; проценты заранее не обещать |
| Windows recovery | Успешное восстановление исходных правил после normal/emergency/restart | Все согласованные сценарии на каждом типе ПК |
| Доступ и экспорт | Попытки чужого device/session, изменённый JSON, revoke | Отказ доступа и отказ проверки подмены |

Изменения политик, согласие участников, доступ к видео и срок хранения заранее согласуются с вузом. AI-флаг не является автоматическим дисциплинарным решением.

## Приёмка среды Windows

Сохранить работу. Независимый launcher, питание, один монитор, свободная камера/микрофон, запас диска. Использовать пустую тестовую флешку и специально открытое безопасное приложение без несохранённых документов.

| Сценарий | Во время теста | После окончания |
|---|---|---|
| Alt+Tab, Win, PrintScreen, запрещённая Ctrl-комбинация | Фактически ограничены; successful block только technical | Обычная работа перней восстановлена |
| Новое запрещённое приложение | Фактически закрыто, разрешённое Moodle продолжает работать | Запуск обычного приложения доступен |
| USB storage | Нельзя прочитать тестовый файл | Исходный доступ восстановлен |
| Разрешённый экзаменационный URL / внешний URL | Вопросы доступны, внешний адрес не открыт | Обычная навигация после завершения |
| Normal submit | Moodle получил ответы; hub/agent terminal, start/end сохранены | Hooks и временная политика сняты |
| Ctrl+Alt+F12 | Аварийное прерывание явно отмечено | Контроль снимается, техническая причина сохранена |
| Потеря камеры/сети/helper | Явный технический статус; не «чистое» завершение | Предсказуемое восстановление/повторный запуск |

Наличие `blocked` в журнале не доказывает фактический запрет. Ctrl+Alt+Del относится к secure desktop и не блокируется обычным hook. Локальный администратор вне гарантируемого периметра.

## Как считать пользу без выдуманных процентов

`часы подготовки = экзаменуемые × медиана подготовки / 3600`.

`часы проверки = эпизоды × медиана review / 3600`.

Сравнивать измерения baseline/пилота; показать объём и диапазон, включить время техподдержки. Денежный эффект считать только с согласованной вузом стоимостью часа и реальными инфраструктурными затратами. Это не готовое утверждение о снижении расходов.

## Қазақша

Финалда бір толық жолды көрсетеміз: Moodle → фото → Start attempt → телефон → тапсыру → мұғалімнің дәлелі/шешімі → есеп. Қалыпты бұғаттау техникалық журналға түседі. Нақты бұзушылықты AI жалғыз шешпейді.

Пилот жоспары: 30 студент, екі сабақ, университеттің LMS әкімшісі мен оқытушысы қабылдайды. Дайындық, нақты старт, жалған оқиғалар/сағат, телефон эпизодтарын табу, review уақыты және Windows қалпына келуі өлшенеді. Кестедегі сандар - мақсаттар, орындалған нәтижелер емес. Үлкен аудитория, антиспуфинг және Platonus туралы дәлелсіз артықшылық айтылмайды.

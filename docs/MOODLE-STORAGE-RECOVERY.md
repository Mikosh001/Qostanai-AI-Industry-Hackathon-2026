# Moodle: отказ запуска при заполненном диске / Диск толғанда Moodle тестін ашу

Проверка: 15 октября 2026 года (Asia/Oral).

## Причина

В локальной демонстрационной среде агент и хаб находятся на C:. Свободного места осталось около 0,26 ГиБ. Хаб возвращал **HTTP 507 Insufficient Storage** на `/api/hub/ingest`: штатный резерв 1 ГиБ защищает запись БД, доказательств и восстановление. Readiness ошибочно сводил этот ответ к временному сетевому сбою и после ожидания показывал «Moodle байланысы қалпына келуде. Тест ашылмады; қайта іске қосып көріңіз».

В той же попытке журнал камеры содержал ошибки OpenCV/NumPy при выделении памяти. Анализатор делал дополнительную полную копию кадра перед блоком обработки исключений, поэтому ошибка копирования могла завершить его поток.

## Исправление

- Старые сгенерированные пакеты в каталоге проекта сжаты штатным **NTFS compression**. Код, записи экзаменов и учётные данные сохранены; сжатие можно отменить командой Windows `compact /U`. Отдельно очищены четыре устаревших сгенерированных installer EXE; предыдущий пакет для отката сохранён. После сжатия свободно около 4 ГиБ до создания нового пакета.
- Резерв диска **сохранён**. Moodle readiness проверяет локальную ёмкость до включения системных ограничений. Ответ хаба 507 хранится с отдельным кодом `hub_storage_low`.
- При нехватке места сообщение объясняет, на этом компьютере или на сервере проблема. Это действие администратора, а не повод бесконечно повторять сетевой запрос. Текст переведён на қазақша / русский / English.
- Сессия остаётся в подготовке, `started` не заполняется. После освобождения места можно повторить действие с той же подготовленной сессией. Историческая ошибка 507 не подменяет текущую временную занятость синхронизации.
- AI-поток удерживает опубликованный кадр по ссылке вместо лишней полной копии. Камера публикует новый кадр, а Vision рисует только на своей отдельной копии. Ошибка выделения памяти внутри анализа обрабатывается, и поток может обработать следующий кадр.
- Тест перезапуска камеры проверяет новые кадры **каждого** запуска с ограниченным ожиданием вместо жёсткого sleep 0,3 с. Проверка скорости захвата остаётся отдельной.

## Проверки

Добавлены регрессии: локальный отказ и повтор после освобождения места; серверный 507 с понятным сообщением и без утечки внутренних путей; старая ошибка 507 при занятом sync lock; немедленный выход из ожидания при постоянном отказе; восстановление AI-потока после MemoryError. Отдельный сценарий настоящего Moodle использует подписанный monitor-профиль и выключенные камеру/микрофон/ограничения ОС. Перед продолжением он проверяет этот профиль, чтобы программная проверка не закрывала приложения пользователя.

**199 Python + 64 desktop + 15 browser = 278 успешных автотестов.** Реальный Moodle: 5 вопросов, по 17 с ожидания на каждом, попытка полностью отправлена, start/end сохранены. Открытие теста — 9532 мс при параллельной сборке installer. Набор относится к указанным программным сценариям.

Фактические результаты текущей проверки сохраняются в `tests/moodle-recovery-2026-10-15.json` и `tests/moodle-recovery-software.json`. Старые SECURITY/VALIDATION-измерения относятся к своим датам.

## Қазақша

Қате Moodle паролінен болған жоқ: C дискісінде шамамен 0,26 ГиБ ғана орын қалған. Sergек хабы деректерді қауіпсіз сақтау үшін 1 ГиБ резерв ұстайды және орын аз болса 507 жауабын береді. Бағдарлама оны уақытша байланыс қатесі деп көрсетіп келген.

Ескі жиналған пакеттер NTFS арқылы сығылып, орын босатылды. Емтихан жазбалары мен жеке файлдар сақталды. Резерв талабы өзгерген жоқ. Енді диск толса, нақты қай жерде орын аз екенін көрсетеді және ұзақ күттірмейді. Орын ашылған соң сол дайындық бетінен қайта басуға болады; емтиханның басталу уақыты оған дейін жазылмайды.

Камера талдауындағы артық кадр көшірмесі алынды. Жад бөлу қатесінен кейін ағынның келесі кадрды өңдеуі жеке тестпен тексеріледі. Бағдарламалық Moodle сынағы нақты камера мен толық Windows қорғанысының қолмен қабылдауын алмастырмайды.

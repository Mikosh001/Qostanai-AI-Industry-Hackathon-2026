# Емтихан басталғанда қосымшаның жабылуы — 1.3.2

2026-10-07. Пайдаланушының соңғы сессиясы дайындық күйінде тоқтаған: USB және RDP шектеулері қосылған, бірақ `session_started` жазбасы жоқ. Electron қате журналы мен Windows Application Error журналында осы тоқтауға сәйкес crash хабарламасы жоқ. Агент және жаңа локалды хаб процесі жоғалған, USB/RDP қайтару журналдары қалған.

Редактордан іске қосылған процестер редактордың Windows Job өмірлік цикліне тәуелді болуы мүмкін. Қорғаныс сол редакторды жабуға әрекеттенгенде емтихан процесі бірге тоқтауы ықтимал. Осы тәуелділік енді жойылады: `Start-Sergek-Demo.cmd` → жеке іске қосқыш → локалды Moodle/хаб → Sergек. Жеке іске қосқыш Windows Explorer өмірлік циклімен ашылады, редактордың Job объектісінде болмауы тексеріледі. Electron өзінің ішкі Job объектісін қолдана алады; ол редакторға тәуелділік ретінде қате қабылданбайды.

Native модуль емтиханның өзін, оның сенімді ішкі процестерін немесе емтихан тәуелді іске қосқышты тоқтатпайды. Соңғы жағдайда бастау қабылданбайды, уақытша шектеулер қайтарылады және таңбашамен қайта ашу туралы түсінікті хабар беріледі. Windows Explorer қалта терезелері бұрынғыдай жабылады; оның shell процесі тоқтатылмайды.

Нақты Windows регрессиясы екі өз сынақ процесін ғана пайдаланды: сынақтағы supervisor Job жабылғанда оған тіркелген процесс тоқтады, ал жеке іске қосылған процесс жұмысын жалғастырды. Native тексерісте емтихан PID, оның баласы, іске қосқыштары және бөтен process тармағы ажыратылды. Desktop бастау/rollback тесттері өтті. Жеке іске қосқыш UAC сұрауын сақтайды; камера, микрофон, USB, перне, экран және қашықтан басқару саясаты әлсіретілмейді.

Алдыңғы тоқтаудан қалған USB/RDP қайтару журналдары нақты native қалпына келтіру арқылы өңделді: `recovery_pending=false`, қате жоқ, екі журнал да алынды. Бұрынғы сессия қайта басталмайды; жаңа логин/емтихан сессиясы ашылады.

Толық жүйелік шектеулерді осы чаттың барлық басқа бағдарламаларын жабатындай іске қосу сынағы орындалмады. Қауіпсіз регрессия тек өз процестерін пайдаланды. Бұл түзету барлық мүмкін аппараттық/драйверлік crash себептерін жоққа шығарады деген тұжырым емес.

Жаңартылған нақты таныстыру іске қосқышымен 1.3.2 ашылды: жеке supervisor расталды, backend health — `ok=true`, баптау қажет емес, барлық қорғаныс жалаушалары қосылған және локалды Moodle логин беті көрінеді. Демо конфигурациясы қосымшаға нақты жолмен беріледі; редактор мен жеке процесс арасындағы AppData көрінісінің айырмашылығына тәуелді емес. Қапталған desktop коды мен native guard құрастыру нәтижесімен салыстырылды. Тексеру нәтижелері: `tests/release-v132-acceptance.json`.

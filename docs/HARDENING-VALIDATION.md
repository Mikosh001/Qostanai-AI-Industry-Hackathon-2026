# Инженерная проверка / Инженерлік тексеріс - 12.10.2026

Проверка основана на предоставленном 9-страничном deep audit, отрицательных тестах и повторном запуске реальной локальной Moodle. Обнаруженные дефекты исправлялись в коде; неудачные нагрузки сохранены. Это отчёт о выполненных сценариях, без обещания нулевых ошибок при любых условиях.

## Что изменилось

- Серверный Moodle Ed25519 grant вместо возможности доверять общему ключу агента. Связь user/quiz/nonce/device/session и реального attempt; отзыв устройства.
- Отдельные короткие lease, incremental sync и неизменная исходная фотография. Долгая загрузка клипа не служит heartbeat.
- Count/head anchors, SHA-256 commitment медиа, ограниченная валидация ZIP, Ed25519 JSON-экспорт. Доверенный ключ нужно получить независимо.
- Staging/шифрование вне общего DB lock, четыре больших загрузки одновременно, резерв диска 1 ГБ, HTTP 507 и явно неполные доказательства. Terminal/control sync не теряет очередь недоставленных клипов.
- Ограниченное ожидание разрешённого Moodle-документа после superseded navigation; защита включается только при Start attempt. UTC start/end сохраняются.
- Callback завершения связан с точным attempt. Отдельный пул восстанавливает потерянный callback, не считая сетевую ошибку успешным завершением.
- Серверная пагинация/поиск и общие счётчики для большого класса; enrollment/revoke в панели. Технические блокировки отделены от событий для review.
- GitHub Windows CI выявил race уже завершённого процесса и неверный запуск test child через `dotnet`. Metadata читается безопасно; живой и уже завершённый дочерние процессы проверяются в framework-dependent и self-contained запусках. Это не тест глобального закрытия чужих программ.

Подробная установка и границы доверия: [TRUST-PROTOCOL.md](TRUST-PROTOCOL.md).

## Метод проверки

Python pytest проверяет API, роли, конкурентность, replay, чужие identity/device/session, malformed packet, неизменность времени, отказ хранения, ограничения архивов, целостность и подпись. Node проверяет desktop URL/навигацию. Playwright проверяет три языка, события, ошибки связи, пагинацию и enrollment/revoke. Полный packaged Moodle сценарий проходит пять вопросов с паузой 17 секунд на каждом, отправляет ответы и проверяет завершение. В программных E2E камера и ограничения ОС явно отключены; эти тесты не доказывают USB/RDP/клавиатурное принуждение.

Машинные результаты последнего прогона помещаются в `tests/results/hardening/`. Они не содержат приватных ключей или видео оператора. Покрытие pytest не равно проценту качества продукта.

## Реальная операторская запись телефона

Добровольный оператор записал около 96 секунд на своей камере. Инструкции не совпали с фактическими моментами показа: интервалы размечены отдельно по визуально просмотренным кадрам с шагом 1 с, переходы исключены. Исходное видео остаётся приватным.

Неизменённый production detector и TemporalRules на 2 sampled FPS обнаружили 4/4 размеченных эпизода: задняя сторона полностью, экран с перекрытием рукой, экран у нижней границы и задняя сторона у нижней границы. На 29,4 с отрицательных интервалов - 0 ложных событий. Frame precision 0,925 / recall 0,778 на коррелированных кадрах. Это одна запись, а не репрезентативный независимый holdout. Для 0 ложных событий верхняя 95% Poisson-граница около 367/час: выборки недостаточно для обещания низкого false-positive rate. Из-за writer/actual FPS исходной записи её шкала ускорена; задержка в реальном времени не измерялась.

Печатная фотография, replay-видео, разные телефоны/камеры/свет, независимые люди и многочасовые отрицательные записи ещё нужны. Три существующих anti-spoof примера не доказывают устойчивость ко всем атакам.

## Нагрузка и граница масштаба

Изолированный временный HTTPS-хаб, четыре независимых процесса генератора, по 100 исходных событий, lease/status раз в 2 с. Один ноутбук: 20 logical CPU / 15,7 ГБ RAM. Media - синтетические ZIP 1 МБ примерно каждые 30 с, без AI/камер/PHP-нагрузки. Результаты нельзя превращать в утверждение о сотнях реальных видеопотоков.

Во время длинного control run выполнялись также функциональные проверки/сборка. Для него сохранён отдельный snapshot исходного кода на старте: старый генератор вычислял hash в конце. В файле результатов записаны оба значения и причина различия. Media run и последующие прогоны фиксируют hash до запуска.

Повтор выполнен без полной PyInstaller/installer сборки и CV-нагрузки; во время него был один короткий .NET build. Backend/генератор фиксированы, все процессы по-прежнему на одном ноутбуке. Повтор также не прошёл. Большая разница между server-processing и end-to-end p95 показывает необходимость отдельно профилировать TLS/генератор/очереди; считать это доказанным пределом исключительно хаба нельзя.

GitHub Windows CI [38245244934](https://github.com/Mikosh001/Qostanai-AI-Industry-Hackathon-2026/actions/runs/38245244934) прошёл на commit `446f780022498c51d451908a74f8db29b27c338e`: backend regressions, npm ci, UI build, desktop tests, native isolated tests и browser acceptance. Это отдельный runner, без физической USB/RDP/keyboard приёмки.

Предельная ёмкость не установлена. Следующий шаг: отдельная машина хаба/генераторов, 30-студенческий пилот с реальными камерами, длительный soak с запасом диска, сбоями сети, контролем восстановления. При большей аудитории нужны измеренные серверные ресурсы и план разделения нагрузки; простое включение нескольких Uvicorn workers с общей текущей SQLite/памятью auth не является готовым масштабированием.

## Что ещё требует приёмки

Физические Windows ограничения и их восстановление; USB, remote tools, второй монитор, secure desktop, чистая установка/upgrade/rollback; университетская Moodle/SSO; Platonus API; полноценное разделение ролей; перенос DPAPI на другой компьютер; Authenticode installer; независимая AI-выборка. Изолированный offline backup/restore полного каталога под той же Windows учётной записью прошёл: secret/media, timestamps, chain/anchor и доверенный report key сохранились (`scripts/Test-Backup-Restore.py`). Локальный администратор/изменённая ОС находятся вне гарантируемого периметра. Device HMAC - аутентификация, не аппаратная аттестация.

Production npm audit: 0 известных уязвимостей. В dev build-chain остаётся один sprintf-js advisory, отображаемый как восемь moderate dependency entries; исправленного upstream релиза advisory не указывает. Закреплённые Python build dependencies прошли pip-audit без известных уязвимостей. Это snapshot баз advisory, не гарантия отсутствия будущих CVE.
